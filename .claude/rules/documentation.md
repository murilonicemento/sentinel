
# Documentation Rules

## Purpose
Keep project documentation accurate and useful.

## General Rules
- Update documentation affected by behavior or contract changes.
- Document non-obvious decisions and important constraints.
- Avoid comments that merely restate the code.
- Prefer examples that can be verified.
- Never document intended behavior as implemented behavior without verification.
